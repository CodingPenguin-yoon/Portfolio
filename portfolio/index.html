01

Chapter 01 · Cloud Operations Gateway

K-Le-PaaS: 명령어를 외우는 운영에서, 문맥을 이해하는 운영으로

K-Le-PaaS Backend Hybrid는 FastAPI 기반 클라우드 운영 자동화 백엔드입니다. GitHub, Kubernetes, Slack, NCP, 모니터링을 연결해 배포, 롤백, 헬스체크, 자연어 명령 실행을 하나의 API 흐름으로 정리했습니다.

문제

GitHub Actions, NCP 콘솔, kubectl, Slack 알림이 흩어져 배포와 롤백 절차가 사람의 기억에 의존했습니다.

해결

FastAPI를 중심으로 REST API, WebSocket, NLP 세션, 명령 이력, 헬스체크, Slack 알림을 통합했습니다.

차별점

한국어 자연어 명령을 Gemini 기반으로 해석하고, Kubernetes/NCP 작업으로 변환해 운영 진입 장벽을 낮췄습니다.

02

Chapter 02 · Git-Based Preview Deployment

Heimdall: 브랜치 업데이트를 실행 가능한 프리뷰 환경으로 바꾸다

Heimdall은 GitHub 또는 GitLab 프로젝트를 등록하고, 추적 브랜치가 업데이트되면 서버에서 Docker 기반 프리뷰 배포를 만들고 상태, 로그, 배포 히스토리, 릴리즈 이미지, 롤백을 관리하는 프리뷰 배포 매니저입니다.

1 Register

GitHub/GitLab 프로젝트와 추적 브랜치를 등록합니다.

2 Build

Webhook 이벤트를 받아 로컬 워크스페이스에서 Docker 이미지를 빌드합니다.

3 Preview

컨테이너 실행, 프리뷰 URL, 로그와 현재 상태를 웹 UI에서 추적합니다.

4 Rollback

릴리즈 이미지와 배포 히스토리를 기준으로 되돌릴 수 있게 합니다.

범위

프로젝트 등록, Webhook 처리, clone/fetch 워크스페이스, Docker 빌드와 컨테이너 실행을 다룹니다.

운영성

프리뷰 URL, 배포 로그, 히스토리, 수동 배포, 자동 배포, 롤백 액션을 UI에서 제어합니다.

데이터

프로젝트별 PostgreSQL 프로비저닝과 deploy-time DATABASE_URL 주입까지 고려했습니다.

03

Chapter 03 · Proxmox Operations & Risk Console

Gjallar: 자동화 이후의 운영 판단을 승인 가능한 제어 흐름으로 만들다

Gjallar는 Proxmox 운영과 리스크를 사람이 안전하게 다룰 수 있게 만든 콘솔입니다. 현재 방향은 DRS Advisor로, Proxmox-native 상태를 기준으로 마이그레이션 추천, 사전 점검, 운영자 승인, Proxmox task 추적, 감사와 reconciliation을 연결합니다.

Observe Inventory

VM, node, storage, HA, task 상태는 Proxmox를 source of truth로 읽습니다.

Decide DRS Advisor

CPU/Memory, policy, risk, route evidence를 기준으로 추천과 pre-check를 만듭니다.

Authorize Approval Gate

실행은 저장된 승인, fresh gate, live evidence, operation lock을 통과한 job에서만 진행합니다.

제품 방향

VMware DRS 대체품이 아니라, Proxmox 운영자를 위한 advisor/control tower로 정의했습니다.

저장하는 것

운영 의도, 정책, 승인, fingerprint, jobs, artifacts, audit, reconciliation 상태를 저장합니다.

구현 기준

read-only inventory를 안전한 기준선으로 두고, mutation은 승인과 검증을 통과한 좁은 경로로 제한합니다.
