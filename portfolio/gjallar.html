Control Tower Flow

위험한 운영 작업은 추천과 실행 권한을 분리해야 한다고 봤습니다.

1

Observe

VM, node, storage, HA, task 상태는 Proxmox에서 읽고 로컬 DB는 운영 의도와 evidence를 저장합니다.

2

Decide

DRS Advisor가 CPU/Memory, policy, risk, route evidence를 기준으로 recommendation과 pre-check를 만듭니다.

3

Authorize

실행은 저장된 승인, fresh gate, live Proxmox evidence, operation lock을 통과한 job에서만 진행합니다.

Implementation Notes

read-only 기준선 위에 좁은 mutation 경로를 만들었습니다.

Source of Truth

실제 VM, node, task, HA, storage 상태는 Proxmox를 기준으로 읽고 로컬에는 운영 상태를 저장합니다.

Approval Packet

추천 결과 자체에는 실행 권한을 주지 않고, 승인 packet과 job intent를 별도로 생성합니다.

Task Tracking

Proxmox UPID 추적, post-check, audit artifact, reconciliation preview로 실행 이후 상태까지 확인합니다.

제품 의미

자동화의 범위를 넓히기보다, 사람이 믿고 승인할 수 있는 운영 제어 흐름을 먼저 세웠습니다.
