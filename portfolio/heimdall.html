Project 02 · Git-Based Preview Deployment

Heimdall

Git 브랜치 업데이트를 Docker 기반 프리뷰 배포와 롤백 가능한 운영 기록으로 바꾸는 매니저

핵심 한 줄

GitHub/GitLab 프로젝트를 등록하고, 추적 브랜치 변경을 감지해 서버에서 빌드, 실행, URL 관리, 로그, 히스토리, 롤백을 하나의 웹 UI 흐름으로 관리합니다.

Repository github.com/CodingPenguin-yoon/Heimdall Role Focus 프리뷰 배포 · Docker 실행 · 배포 기록 · 롤백 제어
Python FastAPI React/Vite Docker PostgreSQL GitHub/GitLab Webhook

Deployment Flow

배포를 한 번의 실행이 아니라 관찰 가능한 상태 변화로 다뤘습니다.

1

Register

GitHub/GitLab 프로젝트와 추적 브랜치를 등록합니다.

2

Build

Webhook을 받아 로컬 워크스페이스에서 clone/fetch와 Docker 빌드를 수행합니다.

3

Preview

컨테이너 실행, 프리뷰 URL, 현재 상태, 배포 로그를 웹 UI에서 확인합니다.

4

Rollback

릴리즈 이미지와 히스토리를 기준으로 이전 상태로 되돌릴 수 있게 합니다.

Implementation Notes

셀프호스팅 가능한 프리뷰 배포 제품의 최소 단위를 구현했습니다.

프로젝트 등록

GitHub/GitLab 프로젝트와 브랜치를 추적 대상으로 등록하고 자동/수동 배포 흐름을 나눴습니다.

런타임 관리

Docker 이미지 빌드, 컨테이너 실행, 프리뷰 URL, 로그 수집을 Heimdall 서버 중심으로 연결했습니다.

데이터베이스

Heimdall 제어 DB와 프로젝트별 PostgreSQL 프로비저닝, deploy-time DATABASE_URL 주입을 고려했습니다.

제품 의미

개발자가 push 이후 결과를 기다리는 구조가 아니라, 배포 상태와 되돌림 경로를 직접 확인하는 구조로 바꿨습니다.
